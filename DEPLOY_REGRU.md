# Запуск «Нормы» на REG.RU — пошагово

Всё можно сделать с телефона: сервер и домен покупаются в браузере, а установку запускает кнопка в GitHub.

## 0. Что заказывать

Обычный хостинг (shared) **не подойдёт**: нужны Docker и браузер Chromium. Нужен **VPS / облачный сервер REG.RU**.

| Параметр | Значение |
|---|---|
| ОС | Ubuntu 22.04 или 24.04 |
| Ресурсы | от 2 vCPU и **4 ГБ ОЗУ** (Chromium прожорлив; на 2 ГБ проверки будут падать), диск от 40 ГБ |
| Дата-центр | **только в России** (Москва / Санкт-Петербург) — это требование ч. 5 ст. 18 152-ФЗ, сервис ведь сам хранит персональные данные |
| Домен | свой домен (можно купить там же в REG.RU) |

Без домена не заработает вход: cookie сессии работают только по HTTPS.

После заказа REG.RU пришлёт **IP-адрес сервера** и **пароль root** (письмо или панель сервера) — они понадобятся в шаге 2.

## 1. Направить домен на сервер

1. В личном кабинете REG.RU откройте управление DNS вашего домена.
2. Добавьте **A-запись**: имя `@` → IP-адрес сервера.
3. Добавьте вторую **A-запись**: имя `www` → тот же IP (адрес с www будет перенаправляться на основной).
4. Подождите 10–60 минут, пока записи разойдутся.

## 2. Установка с телефона через GitHub (рекомендуется)

**Один раз — секреты.** Откройте в браузере телефона `github.com/alexwhite2209/aicheck` → **Settings** → **Secrets and variables** → **Actions** → **New repository secret** и добавьте:

| Секрет | Что вписать |
|---|---|
| `SERVER_HOST` | IP-адрес сервера |
| `SERVER_PASSWORD` | пароль root от сервера |
| `ADMIN_PASSWORD` | придумайте пароль для входа в админку сайта (от 8 символов, без кавычек, `$`, `` ` `` и `\`) |

Необязательно (можно добавить потом и просто запустить Deploy ещё раз):

| Секрет | Зачем |
|---|---|
| `OPENROUTER_API_KEY` | AI-объяснения в отчётах |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | приём оплаты |
| `DADATA_API_KEY` | проверка ЕГРЮЛ/ЕГРИП |

Реквизиты владельца сервиса (обязательно по закону, попадают в политику и согласие) — на той же странице во вкладке **Variables** → **New repository variable**: `OPERATOR_NAME`, `OPERATOR_INN`, `OPERATOR_OGRN`, `OPERATOR_ADDRESS`, `OPERATOR_EMAIL`.

**Запуск.** Вкладка **Actions** → слева **Deploy** → **Run workflow** → впишите домен (например, `norma-audit.ru`) и логин администратора → **Run workflow**.
Это работает и в приложении GitHub для телефона (Actions → Deploy → Run workflow).

Первая установка идёт 10–20 минут: ставится Docker, включается файрвол (открыты только SSH, 80, 443), генерируются пароли базы, собирается и запускается сайт, настраивается ежедневный бэкап. В конце автоматически запускается проверка `deploy/smoke.sh` — она открывает сайт, проверяет API и делает тестовую проверку сайта example.com до PDF.
Зелёная галочка — сайт работает: откройте `https://ваш-домен`. Красный крестик — откройте запуск, внизу будет видно, на каком шаге ошибка.

**Обновление** — тот же Deploy ещё раз. Перед пересборкой делается бэкап базы. Пароли базы и `.env` на сервере сохраняются; секреты и переменные из GitHub подставляются заново.

## 3. Установка вручную по SSH (если без GitHub Actions)

```bash
ssh root@IP-СЕРВЕРА
apt-get update && apt-get install -y git
git clone https://github.com/alexwhite2209/aicheck.git /opt/norma
cd /opt/norma
bash deploy/setup-server.sh      # спросит домен и логин администратора, пароль покажет один раз — запишите
bash deploy/smoke.sh             # ожидание: «Итог: N успешно, 0 с ошибкой»
```

Обновление вручную: `cd /opt/norma && git pull && bash deploy/update.sh`.

## 4. Первые настройки

1. **Вход:** `https://ваш-домен/login` — логин администратора и пароль из секрета `ADMIN_PASSWORD`.
   Регистрация пользователей — только логин и пароль, без email.
2. **Цены** — админка → «Цены».
3. **AI** — модель выбирается в админке → «AI» (ключ — секрет `OPENROUTER_API_KEY`).
4. **Оплата ЮKassa** — после добавления ключей в кабинете ЮKassa укажите адрес уведомлений: `https://ваш-домен/api/payments/webhook` (событие «платёж успешно завершён»). После этого полный отчёт становится платным. Email для кассового чека покупатель вводит при оплате — сервис его не хранит. В чеке указано «без НДС» (`vat_code: 1` в `backend/app/api/payments.py`) — сверьте с вашей системой налогообложения.
5. **Безлимит и пароли пользователей** — админка → «Пользователи». Восстановления пароля по почте нет: забывшему пароль администратор задаёт новый кнопкой «Новый пароль».
6. **Забыли пароль администратора** — поменяйте секрет `ADMIN_PASSWORD` и запустите Deploy: при старте пароль администратора берётся из него.

## 5. Что обязательно сделать владельцу (юридически)

- Сервис сам обрабатывает персональные данные (логины, хеши IP) — вы **оператор ПД**. Направьте уведомление в Роскомнадзор (ст. 22 152-ФЗ) до начала приёма регистраций.
- Сервер должен оставаться в России (см. п. 0). Не подключайте иностранные облака для базы.
- Заполните реквизиты `OPERATOR_*` — без них в политике и согласии стоят заглушки в квадратных скобках.
- Политика и согласие на сайте — шаблоны. Покажите их юристу перед запуском.

## 6. Повседневное (по SSH, в `/opt/norma`)

| Что | Команда |
|---|---|
| Логи | `docker compose logs --tail 100 backend worker caddy` |
| Перезапуск | `docker compose restart` |
| Обновление версии | Deploy в GitHub или `git pull && bash deploy/update.sh` |
| Ручной бэкап | `bash deploy/backup.sh` (копии в `/opt/norma/backups`, хранится 14) |
| Восстановление | `gunzip -c backups/norma-ДАТА.sql.gz \| docker compose exec -T postgres psql -U norma norma` |
| Остановить | `docker compose down` (данные сохраняются) |

Копии `backups/` и файл `.env` скачивайте себе на компьютер — на случай потери сервера.

## Если что-то не работает

- **Deploy красный на шаге «Проверить секреты»** — не добавлен один из секретов из п. 2.
- **Deploy не может подключиться (Permission denied / timeout)** — проверьте `SERVER_HOST` и `SERVER_PASSWORD`; сервер должен быть включён.
- **Сайт не открывается / ошибка сертификата** — домен ещё не указывает на сервер (п. 1). Проверьте `docker compose logs caddy`.
- **Образы не скачиваются** (ошибка Docker Hub) — подождите и запустите Deploy ещё раз; скрипт уже подключил зеркало `mirror.gcr.io`.
- **Проверки зависают/падают** — мало памяти: `free -h` и `docker stats`. Нужно 4 ГБ+.
- **Схема базы** при будущих обновлениях меняется вручную (автомиграций пока нет) — перед обновлением со структурой базы делайте `bash deploy/backup.sh`.
