# Запуск «Нормы» на REG.RU — пошагово

## 0. Что заказывать

Обычный хостинг (shared) **не подойдёт**: нужны Docker и браузер Chromium. Нужен **VPS / облачный сервер REG.RU**.

| Параметр | Значение |
|---|---|
| ОС | Ubuntu 22.04 или 24.04 |
| Ресурсы | от 2 vCPU и **4 ГБ ОЗУ** (Chromium прожорлив; на 2 ГБ проверки будут падать), диск от 40 ГБ |
| Дата-центр | **только в России** (Москва / Санкт-Петербург) — это требование ч. 5 ст. 18 152-ФЗ, сервис ведь сам хранит персональные данные |
| Домен | свой домен (можно купить там же в REG.RU) |

Без домена не заработает вход: cookie сессии работают только по HTTPS.

## 1. Направить домен на сервер

1. В личном кабинете REG.RU откройте управление DNS вашего домена.
2. Добавьте **A-запись**: имя `@` → IP-адрес вашего сервера (он указан в письме/в панели сервера).
3. По желанию вторую A-запись `www` → тот же IP.
4. Подождите 10–60 минут. Проверка: `ping ваш-домен` должен показывать IP сервера.

## 2. Загрузить проект на сервер

На своём компьютере есть архив `norma-deploy.tar.gz` (в папке `rf-audit\dist`). Загрузите его одним из способов:

- **Windows PowerShell:**
  `scp E:\Сайт\rf-audit\dist\norma-deploy.tar.gz root@IP-СЕРВЕРА:/root/`
- или программой WinSCP / FileZilla (SFTP, логин `root`, пароль из панели REG.RU).

## 3. Установить и запустить (одной командой)

Подключитесь к серверу: `ssh root@IP-СЕРВЕРА`, затем:

```bash
mkdir -p /opt/norma && tar -xzf /root/norma-deploy.tar.gz -C /opt/norma
cd /opt/norma
bash deploy/setup-server.sh
```

Скрипт сам: обновит систему, поставит Docker, включит файрвол (открыты только SSH, 80, 443), спросит **домен** и **email админа**, сгенерирует надёжные пароли, соберёт и запустит всё, настроит ежедневный бэкап базы.
Первая сборка — 5–15 минут. **Пароль админа показывается один раз — запишите.**

## 4. Проверить

```bash
bash deploy/smoke.sh
```

Скрипт проверит, что все части работают, и сделает реальную тестовую проверку сайта вплоть до PDF. Ожидание: «Итог: N успешно, 0 с ошибкой».
Затем откройте `https://ваш-домен` (сертификат выпустится сам за 1–2 минуты).

## 5. Первые настройки в админке (`https://ваш-домен/login`)

1. **Реквизиты владельца сервиса** (обязательно по закону): `nano /opt/norma/.env` → заполните `OPERATOR_NAME`, `OPERATOR_INN`, `OPERATOR_OGRN`, `OPERATOR_ADDRESS`, `OPERATOR_EMAIL`, затем `docker compose up -d --build frontend`. Они попадают в политику, согласие и соглашение на сайте (сейчас там заглушки в квадратных скобках).
2. **Цены** — админка → «Цены».
3. **AI**: впишите `OPENROUTER_API_KEY` в `.env`, модель выбирается в админке → «AI». Применить: `docker compose up -d backend worker`.
4. **Оплата ЮKassa**: впишите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`, применить: `docker compose up -d backend worker`. В кабинете ЮKassa укажите адрес уведомлений: `https://ваш-домен/api/payments/webhook` (событие «платёж успешно завершён»). После этого полный отчёт становится платным, а кнопки в плашке тарифов — рабочими.
5. **ЕГРЮЛ**: бесплатный ключ DaData → `DADATA_API_KEY`.
6. Выдать безлимит нужным людям — админка → «Пользователи».

## 6. Что обязательно сделать владельцу (юридически)

- Сервис сам обрабатывает персональные данные (email, хеши IP) — вы **оператор ПД**. Направьте уведомление в Роскомнадзор (ст. 22 152-ФЗ) до начала приёма регистраций.
- Сервер должен оставаться в России (см. п. 0). Не подключайте иностранные облака для базы.
- Политика и согласие на сайте — шаблоны. Покажите их юристу перед запуском.

## 7. Повседневное

| Что | Команда (в `/opt/norma`) |
|---|---|
| Логи | `docker compose logs --tail 100 backend worker caddy` |
| Перезапуск | `docker compose restart` |
| Обновление версии | загрузить новый архив, распаковать поверх, `bash deploy/update.sh` |
| Ручной бэкап | `bash deploy/backup.sh` (копии в `/opt/norma/backups`, хранится 14) |
| Восстановление | `gunzip -c backups/norma-ДАТА.sql.gz \| docker compose exec -T postgres psql -U norma norma` |
| Остановить | `docker compose down` (данные сохраняются) |

Копии `backups/` и файл `.env` скачивайте себе на компьютер — на случай потери сервера.

## Если что-то не работает

- **Сайт не открывается / ошибка сертификата** — домен ещё не указывает на сервер (п. 1). Проверьте `docker compose logs caddy`.
- **Образы не скачиваются** (ошибка Docker Hub) — подождите и повторите `docker compose up -d --build`; скрипт уже подключил зеркало `mirror.gcr.io`.
- **Проверки зависают/падают** — мало памяти: `free -h` и `docker stats`. Нужно 4 ГБ+.
- **Не могу войти** — пароль админа в `.env` (`ADMIN_PASSWORD`), вход по `ADMIN_EMAIL`.
- **Схема базы** при будущих обновлениях меняется вручную (автомиграций пока нет) — перед обновлением со структурой базы делайте `bash deploy/backup.sh`.
