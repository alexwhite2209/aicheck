# LEGAL_DATABASE — нормативная база и методика правил

Документ составлен **до** реализации Rule Engine (п. 58 ТЗ). Rule Engine реализует только правила из этого файла.
Каждое правило опирается на нормы, текст которых выгружен дословно из официального источника и хранится в
`backend/app/legal/data/norms.json` (поле `text`). Параметры правил хранятся в `backend/app/legal/data/rules.json`.

**Дата актуальности всей базы: 03.10.2026.**

## 2. Общие принципы методики

### 2.1. Статусы результата

| Статус | Значение для пользователя | Когда ставится |
|---|---|---|
| `PASS` | 🟢 Выполнено по обнаруженным признакам | Признаки выполнения требования найдены |
| `FAIL` | 🔴 Требование, вероятно, не выполнено | Сайт содержит признаки, однозначно указывающие на невыполнение (с учётом ограничений обхода) |
| `REVIEW` | 🟡 Требует внимания / ручной проверки | Факт установлен, но юридическая квалификация зависит от сведений, недоступных автоматически |
| `UNKNOWN` | ⚪ Не удалось определить автоматически | Публичная часть сайта не позволяет сделать вывод |
| `NA` | Не применимо | Условия применения правила не выполнены (например, нет форм с ПД) |

### 2.2. Уровни уверенности

`confirmed` — подтверждено (факт однозначно зафиксирован краулером);
`probable` — вероятно (вывод сделан по признакам, обход мог не охватить весь сайт);
`manual` — требует ручной проверки;
`undetermined` — не удалось определить.

### 2.3. Ограничения автоматической проверки (действуют для всех правил)

- Анализируется только публичная часть сайта: до 20 страниц, глубина 2, без авторизации, без отправки форм.
- Краулер не выполняет POST/PUT/PATCH/DELETE, не переходит в админку, корзину/checkout, личные кабинеты.
- Отсутствие элемента означает «не найден на проверенных страницах», а не «отсутствует на сайте». Поэтому вывод «отсутствует» имеет уверенность не выше `probable`.
- Сервис не определяет местонахождение серверов по домену/CDN/IP.
- Сервис не имеет доступа к реестрам РКН, внутренним документам оператора, договорам с обработчиками.

### 2.4. Финансовая методика

Каждая сумма имеет: `rule_id`, `legal_basis` (ID нормы КоАП), `calculation_method`, `min_value`, `max_value`, `date` (дата редакции КоАП — 26.07.2026, сверено 03.10.2026).

1. Для каждого правила задана «группа санкции» — конкретная часть статьи КоАП, диапазон которой выгружен дословно.
2. **Тип субъекта** определяется по реквизитам на сайте: ОГРН из 13 цифр / ООО, АО, ПАО → юридическое лицо; ОГРНИП из 15 цифр / «ИП» → индивидуальный предприниматель. Если ИП в части статьи не названы отдельно — применяется диапазон для должностных лиц (примечание к ст. 2.4 КоАП).
3. Состояния:
   - `VERIFIED RANGE` — статус `FAIL`, санкция прямо соответствует проверяемой обязанности, тип субъекта определён по реквизитам;
   - `ESTIMATED RANGE` — тип субъекта не определён (берётся диапазон от минимума для ИП до максимума для ЮЛ) **или** квалификация по конкретной части КоАП не однозначна;
   - `NOT DETERMINABLE` — для обязанности не найдено специальной санкции или денежная оценка некорректна.
4. Если санкция предусматривает предупреждение (ст. 14.8 ч. 1) — `min_value = 0`.
5. **Без двойного счёта**: одна часть статьи КоАП учитывается в сумме один раз, даже если её затрагивают несколько правил (берётся наибольший диапазон в группе).
6. **Финансовая экспозиция** (верх результата) = сумма диапазонов по правилам со статусом `FAIL`.
   **Потенциальная экспозиция** (отдельной строкой) = диапазоны по правилам со статусом `REVIEW`, где санкция возможна, но нарушение не установлено. Не входит в основную сумму.
7. Повторные составы (ч. 1.1, 2.1, 9 и т.д.) не применяются: сервис не знает о прежних наказаниях.
8. Сумма не является прогнозом штрафа: штраф назначает уполномоченный орган с учётом обстоятельств дела.

### 2.5. Score (Russian Website Compliance Score)

Вес правила по критичности: critical = 10, high = 6, medium = 3, low = 1, info = 0.
Оценка правила: PASS = 1, REVIEW = 0.5, FAIL = 0. Правила `UNKNOWN` и `NA` в расчёт не входят (UNKNOWN не считается нарушением).

`Score = round(100 × Σ(вес × оценка) / Σ вес)`. Если взвешенных проверок нет — Score не рассчитывается.

Score отражает только результаты автоматических проверок сервиса и не является официальной оценкой соответствия законодательству РФ.

### 2.6. Тип сайта и наборы правил

Тип определяется по признакам (корзина, цены, schema.org, ключевые слова). Если уверенность ниже порога — `unknown`,
специализированные правила (E-COMMERCE) не применяются. Базовые правила (152-ФЗ, 149-ФЗ, реклама, безопасность)
применяются ко всем сайтам по факту обнаруженных функций.

Режим **E-COMMERCE** включается при типе `online_store` или `marketplace`.

## 3. Правила

Обозначения: «Авто» — что определяется автоматически; «Не авто» — что определить нельзя.

### 152FZ_FORM_PD_001 — Сбор персональных данных через формы
- **Нормативный акт:** 152-ФЗ. **Статья** 3, **пункты** 1, 3 (`152-FZ:3:-:1`, `152-FZ:3:-:3`).
- **Требование:** информация, относящаяся к определяемому физлицу, — ПД; её сбор — обработка ПД.
- **Дата актуальности:** 03.10.2026. **Источник:** ИПС pravo.gov.ru, nd=102108261.
- **Категория:** Персональные данные. **Критичность:** info (в Score не влияет).
- **Авто:** формы и поля (имя, телефон, email, адрес, дата рождения, комментарий и т.п.), обязательность полей, страница.
- **Не авто:** реальная цель обработки, фактическое хранение, относится ли конкретное поле к ПД в контексте.
- **Алгоритм:** найдены формы с полями-ПД → `REVIEW` (`confirmed`: факт сбора установлен; юридическая оценка — в связанных правилах). Не найдены → `NA`.
- **Уверенность:** confirmed (факт), квалификация — ручная.
- **Финансовая методика:** NOT DETERMINABLE.

### 152FZ_POLICY_001 — Политика обработки ПД опубликована и доступна
- **Нормативный акт:** 152-ФЗ, **ст.** 18.1, **ч.** 2 (`152-FZ:18.1:2:`).
- **Требование:** оператор, собирающий ПД через сайт, публикует на страницах сбора документ, определяющий политику обработки ПД, и сведения о реализуемых требованиях к защите ПД, обеспечивает доступ к нему.
- **Дата актуальности:** 03.10.2026. **Источник:** nd=102108261.
- **Категория:** Документы. **Критичность:** high.
- **Применимость:** найдены формы с ПД, вход/регистрация или признаки интернет-магазина.
- **Авто:** ссылки на документ (тексты/URL: «политика», «конфиденциальн», «персональн», privacy, policy), доступность (HTTP 2xx), объём текста, наличие слов «персональн».
- **Не авто:** юридическая достаточность документа.
- **Алгоритм:** документ найден, доступен, содержит текст о ПД → `PASS` (`probable`). Ссылка найдена, но документ недоступен/пустой → `FAIL` (`probable`). Не найден ни на одной проверенной странице и по типовым адресам → `FAIL` (`probable`). Обход прерван до анализа документов → `UNKNOWN`.
- **Финансовая методика:** группа `KOAP:13.11:3:`. VERIFIED при определённом типе субъекта, иначе ESTIMATED (10 000–60 000 ₽).

### 152FZ_POLICY_LINK_002 — Доступ к политике со страниц, где собираются ПД
- **Нормативный акт:** 152-ФЗ, **ст.** 18.1, **ч.** 2 (`152-FZ:18.1:2:`) — «на страницах … с использованием которых осуществляется сбор ПД».
- **Дата актуальности:** 03.10.2026. **Категория:** Документы. **Критичность:** medium.
- **Применимость:** есть формы с ПД и найдена политика.
- **Авто:** наличие на каждой странице с формой ссылки на документ политики.
- **Не авто:** доступ к политике в мобильном приложении, всплывающих окнах, загружаемых по действию.
- **Алгоритм:** ссылка есть на всех страницах с формами → `PASS` (`confirmed`); на части страниц нет → `FAIL` (`probable`), перечисляются страницы.
- **Финансовая методика:** группа `KOAP:13.11:3:` (без двойного счёта с 152FZ_POLICY_001), ESTIMATED.

### 152FZ_POLICY_CONTENT_003 — Содержание политики соответствует обнаруженной обработке
- **Нормативный акт:** 152-ФЗ, **ст.** 18.1, **ч.** 2 (`152-FZ:18.1:2:`).
- **Требование (прямое):** опубликованы сведения о реализуемых требованиях к защите ПД.
- **Дата актуальности:** 03.10.2026. **Категория:** Документы. **Критичность:** medium.
- **Применимость:** политика найдена и доступна.

- **Финансовая методика:** группа `KOAP:14.8:1:`, ESTIMATED.

### ECOM_RETURN_INFO_004 — Порядок и сроки возврата товара
- **Нормативный акт:** Закон 2300-I, **ст.** 26.1, **п.** 4.
- **Требование:** потребитель вправе отказаться от товара до передачи и в течение 7 дней после; без письменной информации о порядке и сроках возврата при доставке — в течение 3 месяцев.
- **Дата актуальности:** 03.10.2026. **Категория:** Потребители. **Критичность:** low (high — если найден срок менее 7 дней).
- **Авто:** раздел о возврате; указанный срок возврата.
- **Не авто:** вручается ли информация в письменной форме при доставке; категории товаров с индивидуально-определёнными свойствами.
- **Алгоритм:** найден срок возврата менее 7 дней → `REVIEW` (`probable`, критичность high); раздел не найден → `REVIEW` (`manual`); найден, срок ≥ 7 дней или не указан → `PASS` (`probable`).
- **Финансовая методика:** NOT DETERMINABLE.

### ECOM_NATIONAL_PAYMENT_005 — Оплата национальными платёжными инструментами
- **Нормативный акт:** Закон 2300-I, **ст.** 16.1, **п.** 1.
- **Требование:** возможность оплаты национальными платёжными инструментами; обязанность в части НСПК распространяется на продавцов с выручкой за прошлый год более 20 млн ₽.
- **Дата актуальности:** 03.10.2026. **Категория:** Интернет-магазин. **Критичность:** low.
- **Применимость:** режим E-COMMERCE и признаки онлайн-оплаты.
- **Авто:** упоминание «Мир», СБП, оплаты при получении.
- **Не авто:** выручка продавца, фактические способы оплаты на шаге оплаты.
- **Алгоритм:** упоминание найдено → `PASS` (`probable`); нет → `REVIEW` (`manual`).
- **Финансовая методика:** потенциальная, группа `KOAP:14.8:4:`, ESTIMATED.

### SEC_HTTPS_001 — Защищённое соединение при передаче ПД
- **Нормативный акт:** 152-ФЗ, **ст.** 19, **ч.** 1.
- **Требование:** оператор принимает необходимые технические меры защиты ПД от неправомерного доступа.
- **Дата актуальности:** 03.10.2026. **Категория:** Информационная безопасность. **Критичность:** high при наличии форм с ПД, иначе low.
- **Авто:** HTTPS, редирект с HTTP, валидность сертификата, протокол отправки форм (`action`).
- **Не авто:** иные меры защиты (система защиты ИСПДн, уровень защищённости).
- **Алгоритм:** форма с ПД на HTTP-странице или с HTTP-`action`, либо сайт без HTTPS → `FAIL` (`confirmed`); невалидный сертификат → `FAIL` (`confirmed`); HTTPS есть, но HTTP не перенаправляет → `REVIEW` (`probable`); всё в порядке → `PASS` (`confirmed`).
- **Финансовая методика:** NOT DETERMINABLE.

## 4. Не включено в MVP (кандидаты, требуют отдельной сверки)

Не реализуются до подтверждения нормативного основания и методики:
- согласие на распространение ПД (ст. 10.1 152-ФЗ) и требования РКН к его содержанию;
- маркировка материалов иностранных агентов (ст. 10 ч. 7 149-ФЗ);
- требования к русскому языку информации для потребителей (изменения 53-ФЗ и Закона 2300-I);
- отраслевые требования (медицина, образование, финансы, недвижимость, СМИ): лицензии, раскрытие информации;
- требования к агрегаторам информации о товарах (п. 22 абз. 4–5, п. 24 Правил ПП № 657).

## 5. Порядок обновления

Нормативная база → новая редакция (новая запись нормы с `effective_from`) → новая версия правила (`rule_versions`, статус `draft`) →
тестирование (unit-тесты правила должны пройти) → публикация администратором (`published`; у предыдущей версии
проставляется `effective_to`). Старые версии не перезаписываются. Результат аудита хранит ID версий правил
и редакции норм, применённые в момент проверки. AI не имеет доступа к изменению правил.
