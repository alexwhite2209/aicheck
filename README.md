# Норма — AI-аудитор сайтов по законодательству РФ

Пользователь вставляет URL → сервис открывает сайт в Chromium, собирает факты → сопоставляет их с правилами,
основанными на нормах в действующей редакции (pravo.gov.ru) → показывает Score, финансовую экспозицию, проблемы,
нормативные основания, рекомендации и пункты, которые невозможно определить автоматически. PDF-отчёт, кабинет, админка.

```
ФАКТЫ С САЙТА → НОРМАТИВНОЕ ПРАВИЛО → ПРОВЕРКА → ДОКАЗАТЕЛЬСТВО → AI-ОБЪЯСНЕНИЕ
```

- **[LEGAL_DATABASE.md](LEGAL_DATABASE.md)** — нормативная база и методика каждого правила (составлена до Rule Engine).
- `backend/app/legal/data/norms.json` — дословные выдержки 38 норм из ИПС «Законодательство России», редакции на 03.10.2026.
- `backend/app/legal/data/rules.json` — 23 правила: основания, критичность, санкции КоАП.

## Запуск в Docker

```bash
cp .env.example .env   # заполнить POSTGRES_PASSWORD, JWT_SECRET (32+ символа), ADMIN_LOGIN/ADMIN_PASSWORD
docker compose up -d
```

Сервисы: `frontend` (Next.js, порт 3000), `backend` (FastAPI), `worker` (Celery + Playwright/Chromium), `postgres`, `redis`.
Сайт: http://localhost:3000, админка — `/admin` (вход под ADMIN_LOGIN).

HTTPS с сертификатом Let's Encrypt: в `.env` задать `DOMAIN=example.ru`, `PUBLIC_BASE_URL=https://example.ru`,
`TRUST_PROXY_HEADERS=true`, затем `docker compose --profile https up -d` (Caddy на 80/443).

## Локальная разработка (без Docker)

```bash
cd backend && python -m venv .venv && .venv/Scripts/pip install -r requirements.txt && .venv/Scripts/python -m playwright install chromium
.venv/Scripts/python -m uvicorn app.main:app --port 8000          # SQLite + задачи в потоках (TASK_MODE=inline)
cd ../frontend && npm install && npm run dev                       # http://localhost:3000, /api проксируется на :8000
```

Тесты backend: `.venv/Scripts/python -m pytest` (136 тестов: каждое правило, SSRF, финансы и Score, извлечение фактов, API).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | AI-объяснения. Без ключа отчёт строится по шаблонам правил. Модель меняется в админке |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Оплата. Без ключей полный отчёт открыт всем, кнопка оплаты скрыта |
| `JWT_SECRET`, `IP_HASH_SECRET` | Подпись сессий; соль для хеширования IP (IP в открытом виде не хранится) |
| `OPERATOR_*` | Реквизиты оператора сервиса для политики, согласия и соглашения (сейчас на страницах — заглушки в квадратных скобках) |
| `TASK_MODE` | `celery` (Docker) или `inline` (локально) |

## Архитектура

```
frontend (Next.js 16) ──/api/*──▶ backend (FastAPI) ──▶ Redis/Celery ──▶ worker
                                      │                                  │
                                 PostgreSQL ◀── результат ── Rule Engine ◀ факты ◀ crawler (Playwright → egress-прокси)
                                                      │
                                               OpenRouter (только backend)
```

- `backend/app/crawler/` — `browser.py` (обход до 20 страниц, глубина 2, 30 с/страница, 180 с всего), `egress_proxy.py`
  (сеть Chromium только через прокси: сам резолвит DNS, пускает лишь публичные IP на портах 80/443 — защита от SSRF и DNS rebinding),
  `ssrf.py`, `page_extract.js` (формы, ссылки, скрипты, cookie-баннер, реклама), `extract.py` (единый объект фактов),
  `signatures.py` (справочник сервисов с юрисдикцией компании-владельца), `requisites.py` (ИНН/ОГРН с контрольными суммами), `site_type.py`.
- `backend/app/legal/` — `rules.py` (алгоритмы правил), `engine.py` (применение опубликованных версий на дату), `finance.py`,
  `score.py`, `seed.py`, `fixtures.py` (тест-наборы для каждого правила, используются pytest и кнопкой «Тест» в админке).
- `backend/app/ai/openrouter.py` — промпт с запретами; ответы со ссылками на нормы вне переданных, суммами или «гарантиями» отбрасываются.
- `backend/app/pdf/report.py` — PDF (ReportLab): URL, дата, тип, Score, экспозиция, проблемы, доказательства, нормы, рекомендации,
  неопределённые пункты, методология, disclaimer.

## Тарифы

| Тариф | Цена | Что получает |
|---|---|---|
| Экспресс-проверка | 0 ₽ | Базовая проверка соответствия законодательству РФ |
| Полный аудит | 299 ₽ | Законодательство РФ + Security Skills + реестры + финансовая экспозиция + полный PDF-отчёт |
| Повторная проверка | 499 ₽ | Полный повторный аудит + сравнение с предыдущим результатом |

Цены хранятся в БД и меняются в админке. Отдельного тарифа на проверку безопасности нет — она входит в «Полный аудит».
Вход и регистрация — только **логин + пароль**; email не требуется (для кассового чека ЮKassa email вводится при оплате и не сохраняется).

## Security Skills и реестры (входят в «Полный аудит»)

См. **[SECURITY_CHECKS.md](SECURITY_CHECKS.md)**. 10 пассивных направлений + внутренний триаж. Сервис открывает сайт,
смотрит только то, что он сам публично отдаёт, фиксирует факт, сопоставляет и даёт рекомендацию. Активных проверок
(XSS, SQL-инъекции, Host header, активные IDOR/BOLA, любая эксплуатация) нет. Код — `backend/app/secaudit/`
(`collect.py` — безопасные GET во время обхода; `scan.py` — детект; `engine.py` — триаж + Security score + связь с 152-ФЗ ст. 19).

- **Реестры** (`secaudit/registries.py`): домен через RDAP (.ru/.рф, публично), ЕГРЮЛ/ЕГРИП по ИНН (через `DADATA_API_KEY`,
  иначе ссылка на egrul.nalog.ru), реестр операторов ПД РКН (капчу не обходим — прямая ссылка).

## Обновление законодательства

Админка → «Нормативная база» → новая редакция нормы (текст дословно, источник только pravo.gov.ru или *.gov.ru) →
«Rules» → новая версия правила (черновик) → «Тест» (unit-наборы правила) → «Опубликовать».
Старая версия получает `effective_to` и сохраняется; аудиты хранят применённые версии правил и редакции норм.
AI не может менять правила. Новое правило — сначала описание в LEGAL_DATABASE.md и реализация алгоритма в `rules.py`.

## Безопасность

SSRF-защита (валидация URL + egress-прокси + блокировка не-GET в браузере), только безопасные запросы к проверяемому сайту,
пропуск админок/корзин/кабинетов, rate limiting (IP-хеш, пользователь, проверяемый домен), httpOnly-сессии + CSRF (double submit),
хеш паролей scrypt, валидация ввода (Pydantic), ORM без сырых SQL, CSP/заголовки безопасности, журнал действий (`audit_log`),
секреты только на backend. IP-заголовкам доверять только за своим реверс-прокси (`TRUST_PROXY_HEADERS=true` за Caddy/nginx).

## Персональные данные самого сервиса

IP хранится только в виде HMAC-хеша; анонимные проверки удаляются через 30 дней; при регистрации — отдельное согласие на ПД и
отдельное (необязательное) на рассылки; выгрузка и удаление аккаунта в кабинете; без сторонней аналитики, шрифты самохостятся;
базы данных должны размещаться на серверах в РФ (ч. 5 ст. 18 152-ФЗ). Перед запуском заполните реквизиты оператора (`OPERATOR_*`)
и направьте уведомление в Роскомнадзор.

## Ограничения MVP

- Мониторинг: настройка частоты сохраняется, автоматический запуск проверок — следующий этап.
- Генерация документов (политика/согласие) — не реализована.
- Отраслевые требования (медицина, образование, финансы, СМИ) и иные кандидаты перечислены в LEGAL_DATABASE.md, раздел 4.
